# Coding Agent 运行时学习指南

这组文档只解释当前项目的智能体运行逻辑，不讲 FastAPI、Vue、页面布局或普通数据库增删改查。

依据题目 PDF，评委最关注两件事：

1. 你是否真正理解 Agent 为什么能连续完成编程任务；
2. 你能否为上下文、工具、解析、终止和错误处理等设计作出辩护。

## 先记住这一句话

> 模型提出下一步动作，项目校验并在本机执行动作，再把事实结果交还模型；项目始终掌握上下文、权限、预算和终止权。

这句话把项目中最容易混淆的角色分开了：

| 角色 | 负责什么 | 不负责什么 |
|---|---|---|
| DeepSeek 模型 | 根据已有消息决定回复文本或提出工具调用 | 不直接读取文件、不直接执行命令、不决定权限 |
| Agent 控制器 | 维护循环和消息历史，解析模型意图，检查预算，决定继续或终止 | 不替模型编写解决方案 |
| 工具系统 | 在本地执行文件搜索、读取、修改和命令，并返回结构化事实 | 不自行决定下一步任务策略 |
| 权限策略 | 决定某个动作允许、需要确认还是拒绝 | 不是操作系统沙箱 |
| 上下文 | 给模型提供当前任务、可见历史、记忆和工具结果 | 不是模型内部永久记忆 |

## 用 30 秒介绍当前 Agent

当前项目从零实现了一个有边界的编程 Agent。每轮把完整运行历史和六个本地工具定义发送给 DeepSeek。模型如果返回普通文本，控制器结束；如果返回工具调用，项目在本地校验参数、工作区和权限，执行后把 JSON 结果加入历史，再请求下一轮模型。整个过程受模型次数、工具次数、Token、总时间和取消信号约束，并对协议错误、API 错误和工具错误分别处理。

## 用 2 分钟介绍当前 Agent

可以按下面顺序说：

1. 用户选定工作区并提交任务，本次运行同时冻结权限、可见历史和工作区记忆。
2. 运行器为这次任务新建 DeepSeek 适配器、工具注册表和预算配置，避免不同运行共享可变状态。
3. 控制器构造初始消息：系统规则、作为不可信资料提供的历史、带可选记忆的当前任务。
4. 控制器循环请求模型。模型只能选择最终回答，或者调用项目声明的六个函数工具。
5. 工具调用不会交给模型厂商执行，而是在本机经过严格 JSON、路径、权限和命令风险判断后执行。
6. 工具成功或失败都会形成统一 JSON 结果回填，因此模型能看到真实结果并调整策略。
7. 控制器根据 `finish_reason`、协议结构、预算、取消和错误类型决定继续、重试或终止。
8. `model_final` 只代表模型不再调用工具，不代表代码必然正确；正确性还需要测试或独立验收。

## 当前实现的源码入口

不需要一开始阅读所有细节。理解文档后，只需知道以下文件分别承担什么职责：

| 文件 | 运行时职责 |
|---|---|
| `agents/agent.py` | Agent 主循环、预算、工具回填和终止 |
| `agents/context.py` | 历史与记忆的有界上下文 |
| `agents/contracts.py` | 模型、工具和运行结果使用的数据 |
| `agents/providers/deepseek.py` | DeepSeek 请求与响应整理 |
| `agents/tools/` | 六个本地工具及统一工具协议 |
| `agents/security/` | 工作区边界、命令分类和三档权限 |
| `agents/progress.py` | 完全重复工具交换检测 |
| `agents/runtime/agent_runner.py` | 为一次运行创建上述对象 |

## 阅读时避免三个误区

- 不要把“模型”叫作整个 Agent。模型只是决策组件，循环和执行器同样属于 Agent。
- 不要把“模型 final”叫作“任务验证成功”。它只说明模型选择停止调用工具。
- 不要把“权限策略”叫作“安全沙箱”。它能限制项目自己的工具，但不能取代容器、虚拟机或受限系统账户。
